## 2. 이미지↔월드 매핑 확립

토폴로지를 논하려면 먼저 좌표계를 맞춰야 했다. `track.world`의 실제 지오메트리:

```xml
<model name="ground">
  <pose>0 0 0 0 0 1.57</pose>        <!-- z축 90도 회전 -->
  <plane><size>58.1364 43.71084</size></plane>
```

90° 회전 때문에 평면의 로컬 x축이 월드 **+y**로, 로컬 y축이 월드 **−x**로 간다.
(`models/race_track/model.sdf`의 55.08×36.02는 쓰이지 않는다 — world 파일이 자체 정의를 갖는다.)

```
u = (world_y + 29.068) / 58.1364 * 2346
v = (21.855 + world_x) / 43.71084 * 1759
```

**검증**: 15개 존을 전부 투영한 결과 —
링 존 8개(Start, M2, T2, M3, crosswalk, T4, T3, T1/M1)는 **전부 어두운 포장면**,
내부 존 7개(IN, OUT×2, Slot1–4)는 **전부 회색 주차구역**(rgb 120,121,125).
15/15 일치. 우연히 맞을 수 없는 분리다.

## 3. 실제 토폴로지

### 3.1 개구부는 없다

IN 표시 주변을 확대해 보면 링과 주차구역 사이 **흰 경계선이 끊김 없이 이어진다.**
그리고 `track.world`에는 지면 평면 외에 **충돌 지오메트리가 없다** — 선은 순수하게 그림이다.

→ **차는 링에서 주차구역으로 어디서든 넘어갈 수 있다.** `IN →`은 물리적 입구가 아니라
"여기로 들어가라"는 **의미 표시**다.

이것은 계획 §3.2가 서수 축의 근거로 삼은 "개구부 앞에서 관측이 픽셀 단위로 동일"이라는 구성을
불가능하게 만든다. 셀 개구부가 없기 때문이다.

### 3.2 IN/OUT은 관통 통로다

| 표시 | world | 이미지상 위치 |
|---|---|---|
| IN | (−2.76, −17.60) | 주차구역 **좌측**(T3·횡단보도 쪽), 화살표가 오른쪽을 가리킴 |
| OUT(통과직전) | (−1.91, +12.19) | 주차구역 **우측** |
| OUT(통과직후) | (−1.92, +17.94) | 주차구역 우측, 링에 더 가까움 |

즉 의도된 흐름은 **좌측 진입 → 주차구역 횡단 → 우측 진출**이다.
같은 변에 개구부 2개가 있는 구조가 아니다.

### 3.3 주차구역 제원

```
world x [-13.48, +13.48]   y [-19.63, +14.84]     약 27.0 x 34.5 m
```

### 3.4 주차 베이 — 실측

world x=3.40 열을 훑어 흰 선 5개를 찾았다:

| 베이 | 중심 y | 폭 |
|---|---|---|
| Bay1 | −9.36 | 3.63 m |
| Bay2 | −5.72 | 3.64 m |
| Bay3 | −2.09 | 3.62 m |
| Bay4 | +1.54 | 3.65 m |

`zone_map.yaml`의 Slot1–4(−9.42 / −5.76 / −2.19 / +1.55)와 **6 cm 이내 일치**.
**간격 3.63 m로 균일하고, 4개가 시각적으로 동일하다.**

이미지상 주차구역 상단에 **두 번째 베이 그룹 4개**가 더 있다(가로 방향). `zone_map.yaml`에는 없다.

## 4. 서수 축을 살리는 방법 — 베이로 옮긴다

계획 §3.1의 판정 규칙은 그대로 유효하다:

> 언어 축이 기준 (c)에 기여하는 것은, instruction이 **관측 이력으로부터 복원 불가능한**
> 프레임에서뿐이다.

개구부가 없어졌지만, **균일 간격의 동일한 베이 4개**가 그 조건을 그대로 만족한다.

`"park in the second bay"` vs `"park in the fourth bay"`
- 접근 구간의 이미지는 **동일하다**
- 몇 번째인지는 **세어야만** 알 수 있고, 세는 기준은 instruction뿐이다
- 관측 어디에도 답이 없다 → **non-separable**

계획이 Slot1 vs Slot2를 기각했던 근거(§3.3 "3.6 m 간격 한 줄, 마지막 몇 미터에서만 분기")는
**divergence 크기**에 대한 것이었다. 서수 축에서 중요한 것은 크기가 아니라 **언어가 유일한
정보원이라는 사실**이다. 두 목적이 다르므로 기각 사유가 그대로 적용되지 않는다.

다만 divergence가 국소적인 것은 사실이므로, **크기는 경로 분기 축이 담당하고 서수는 기준 (a)의
증거를 담당**하도록 역할을 나눈다.

### 수정된 축 구성

| Tier | 축 | 근거 | 상태 |
|---|---|---|---|
| 1-A | **베이 서수** `"the second bay"` | 유일하게 관측으로 복원 불가. 4개 균일·동일 | 기반 확인됨 |
| 1-B | **링 vs 주차구역 횡단** | 42 m 관통 vs 64–74 m 우회. 분기 후 지속 | 물리 장벽 없이 성립 (그림만 있어도 정책은 학습 가능) |
| 2 | 속도 | 시간축 조밀 | 변경 없음 |
| — | ~~개구부 서수~~ | **물리적 기반 없음** | **폐기** |

## 5. 남은 확인 사항

1. **두 번째 베이 그룹의 좌표 미측정.** 주차구역 상단 가로 베이 4개. `zone_map.yaml`에 없다.
   좌/우 분기(BayGroupA vs B)를 쓰려면 측량해야 한다.
2. **링 vs 주차구역 분기점을 어디로 정할지.** 물리적 개구부가 없으므로 **우리가 정해야 한다.**
   IN 표시(−2.76, −17.60) 부근이 자연스럽다 — 텍스처에 화살표가 그려져 있어 시각적 단서가 있다.
3. **경계선을 넘는 주행이 "off_track"인지.** 충돌이 없으므로 물리적으로는 자유롭다.
   `termination` 판정 기준을 정의해야 한다(계획 §10-5가 지적한 "시뮬에서 도로 이탈에 대가가 없다").
