# 2026-08-04 18:30 — 진범: 검증 사각지대의 크루즈 이탈 에피소드 16개 (라벨 오염)

[06:30 문서](20260804_0630_v4b-refutes-recipe-epoch-parity.md)의 에포크 가설도 기각됐다.
v4c(80K, 8.2 epoch 등가)가 **4회 전부 트랙 이탈로 최악** — 스텝을 늘릴수록 나빠졌다.
그 역설이 단서였다: 모델은 배운 대로를 더 충실히 실행했을 뿐이다. 문제는 배운 내용이었다.

## 탐색 경로 (기각 순서)

1. lerobot 변환 무결성 — 액션·상태 완전 일치, 이미지 시프트 0 → 무혐의
2. 수집 시점 간 코드 변화(Ackermann 등) — 커밋 7/17, 두 수집 모두 이전 → 무혐의
3. 선생 주행 라인 orig vs supp — 중앙값 차 0.05 m로 일치. 그런데 히스토그램 꼬리에
   **횡편차 −25~−33 m** 프레임 발견 → 링 위에 있을 수 없는 좌표

## 진범

링에서 3 m 이상 벗어난 프레임을 역추적하니 **10개 에피소드에 집중** (orig 4 + supp 6),
y5j 분기점 팩에서도 6/48. 공통점:

- **전부 크루즈** (goal-less), **전부 lane1(안쪽/왼쪽) 지시**
- 60~78프레임(6~8초)째부터 에피소드 끝까지 링 밖 — 대부분 OUT 출구 도로(x 16~38)로 이탈
- **크루즈는 시간 경과 = success**라 검증을 통과, "왼쪽 차선으로 계속 주행" 라벨을 단
  링 이탈 시연 ~1,600 프레임(2%)이 코퍼스에 포함됨

즉 **선생 욜로 스택 자체가 목표 감독 없는 lane1 크루즈에서 OUT 분기점을 ~25% 확률로
놓친다** (y5j에서 분기점 통과를 강제하자 실패율이 그대로 드러남). 존 에피소드는
navigator가 경로를 교정하고 도착 검증도 있어 안전했다.

이것으로 전부 설명된다:
- v4 계열 이탈 지점(+21, y −8~+4) = 오염 에피소드들의 이탈 경로와 일치
- 스텝↑ → 오염 모방 충실도↑ → v4c가 최악
- v3y-40K도 오염 3~4개를 안고 있었고, 그 흔적이 분기점 최대편차 −2.68 m
- 통계 감사(분포·액션·정렬)가 전부 통과한 이유: 오염은 2%의 꼬리라 집계에 안 보였다

## 조치

1. **클린 코퍼스 v5** = packed_v3y + packed_y5j − 오염 16 = **372 eps** →
   `lerobot/v5` 변환 → `navvla_smolvla_v5` 60K 학습 (기동 18:20경, 완료 ~새벽)
2. **수집기 가드**: `collect_corpus.py`에 off-ring 검증 추가 — 링 중심선에서
   3 m 초과가 2초 지속되면 `termination="off_ring"` 실패 처리 (park_bay 제외).
   앞으로 크루즈도 검증 사각지대 없음
3. 서버 정리: v4c 중간 체크포인트·lerobot/v4 삭제 (여유 40 G 유지)

## 교훈

- **"success"의 정의가 과업마다 달라야 한다.** 도착 검증이 없는 과업(크루즈)은
  별도의 불변식(링 위에 있을 것)을 명시적으로 검증해야 한다
- 집계 통계는 꼬리 오염을 못 본다 — 히스토그램의 꼬리가 신호였다
- 실패 재현 위치가 데이터의 실패 위치와 일치하면, 모델이 아니라 데이터를 파라
