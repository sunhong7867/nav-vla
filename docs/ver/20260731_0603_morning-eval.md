# 2026-07-31 06:03 — 밤새 두 모델 평가: v2c 음성, v21b 에포크 가설 확증

밤새 완주한 v2c(hold 45 + 말단 ×2)와 v21b-80K(연장)를 같은 하네스로 평가했다.

## 1. v2c — 음성 결과. 크리프는 데이터 가중만으로 못 잡는다

```
8회 전부 bay3 부근으로 붕괴 (y −0.2 ~ −2.6), 대각선 소멸, 정지 0/8
```

hold 45 + 말단 6초 ×2 복제는 말단·정지 프레임 비중을 크게 올렸고, 그만큼 **주행·서수
학습이 희석**됐다. 데이터가 커진 만큼 같은 40K 스텝의 에포크도 1.97로 줄었다.
v2b(hold 15, 3.0 에포크)의 8/8에서 **후퇴**했다.

> **기록할 결론**: 이 규모(주차 229 에피소드)에서 정지 신호를 데이터 가중으로 키우면
> 주행 능력과 상충한다. 크리프의 종결은 다른 경로가 필요하다 — 후보: (a) 더 긴 학습으로
> 양쪽 모두 수렴, (b) 정지 상태의 관측 다양화(hold 프레임에 카메라 노이즈/조도 변형),
> (c) 실차에서는 모터 데드밴드가 물리적으로 흡수할 가능성 (0.05 m/s는 실모터 정지마찰
> 이하) — 시뮬 순수성 문제일 수 있다.

v2c 라인은 폐기. 체크포인트는 서버에 보존만.

## 2. v21b-80K — 에포크 가설 확증

| | 40K (주차 노출 1.3ep) | **80K (2.6ep)** | 참조 v2b (3.0ep) |
|---|---|---|---|
| 주차 최근접 정답 | ~4/8 | **~6/8** (bay1 회복 2/2) | 8/8 |
| 링 차선 분화 | 3.1× | **3.8×** (0.906 m) | — |
| 링 추종 | O | O (20.3 m/30 s) | ✕ |

**주차 노출 에포크에 비례해 회복**한다 — 40K 시점의 "링 데이터가 주차를 해친다"는
해석은 틀렸고, 단지 덜 익었던 것이다. 이탈 1회(bay4 1차: 맵 밖 −7.9,10.7)는 남은
불안정성으로 기록.

**→ 120K 연장 실행** (주차 노출 3.9 에포크). v2b의 8/8 발현점(3.0)을 넘긴다.
완료 ~11:30, 그때 4칸+링 재평가로 통합 데모 모델 판정.

## 3. 정지 문제의 현재 위치 (정직한 요약)

- 정지 스킬은 **open-loop으로는 존재** (정지 화면+속도 0 → 0.003 m/s)
- 폐루프에서는 어느 모델도 3 s/0.15 m 기준을 통과하지 못함 — v2b는 올바른 칸에서
  0.05~0.08 m/s 크리프, 나머지는 그 이전 단계
- 데모 관점: v2b는 "말한 칸에 들어가 서행 상태"까지 도달하므로 시연 가능. 운전자
  종료('' 발행)는 조작이지 규칙이 아니므로 기준 (d) 무관

## 4. 운영 (재발 3회차 → 메모리 승격)

아침 평가 체인이 **자기 pkill에 자살**했다 — 인라인 `bash -c` 본문이 /proc/cmdline에
그대로 실려 pkill 패턴이 자신을 매칭. 파일 스크립트로 재작성 후 정상 완주.
세 번째 재발이므로 프로젝트 메모리에 규칙으로 저장: **오케스트레이션은 파일 스크립트로,
인라인에 pkill 패턴 금지, 런처 exit code 불신·대상 상태 검증.**
