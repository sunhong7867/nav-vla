# 2026-07-28 21:15 — 주차 진입 기하 수정 (실주행 관찰에서 나온 3건)

> 앞선 문서: [19:27 링 커넥터](20260728_1927_ring-connector.md)
> 이 문서는 [19:06 주차칸 서수 축](20260728_1906_parking-ordinal.md) §4의 진입 경로 설계를
> **정정한다.** 그 문서의 표(통로 x=−2.50, 반경 2.65 m, 정지 x=5.27)는 더 이상 유효하지 않다.

세 건 모두 **시뮬레이터 화면을 보고 발견됐다.** 계측 스크립트는 전부 통과하고 있었다 —
`arrived`가 떴고, 반사실 발산도 정상이었다. 경로가 차가 따라갈 수 있는지, 차체가 칸 안에
들어가는지를 아무도 재고 있지 않았기 때문이다.

## 1. 정지 지점 — 차를 점으로 취급했다

`stop_x = BAY_BACK_X − 1.2 = 5.27`. "뒷벽에서 1.2 m 앞"이라는 뜻으로 썼는데, 그 1.2 m는
**차량 기준점**에서 잰 것이지 범퍼에서 잰 게 아니다.

```
기준점 → 코끝  2.269 m       (CAR_NOSE_AHEAD)
기준점 → 꼬리  2.349 m       (CAR_TAIL_BEHIND)
전장          4.618 m
칸 깊이       5.66 m         (BAY_OPEN_X 0.81 → BAY_BACK_X 6.47)
```

정지점 5.27 → 코끝 **7.54**, 뒷벽 6.47. **1.07 m 밖으로 나간다.**

아무것도 충돌하지 않아서 안 보였다. 차체 collision box는 2.1 m뿐이라 실제 물리 접촉이 없다.
사용자가 화면에서 발견했다.

수정: 칸 중앙 정지.

```python
stop_x = 0.5 * (BAY_OPEN_X + BAY_BACK_X)          # 3.64
lo, hi = BAY_OPEN_X + CAR_TAIL_BEHIND, BAY_BACK_X - CAR_NOSE_AHEAD
assert lo <= stop_x <= hi                          # 3.16 <= 3.64 <= 4.20
```

여유가 앞 0.56 m / 뒤 0.48 m밖에 없다. **가능한 정지점의 폭이 1.04 m뿐**이라는 뜻이고,
`stop_x`를 눈대중으로 고르면 안 되는 이유이기도 하다. 생성기가 이제 이 부등식을 검사하고
위반하면 `clear_front_m` / `clear_rear_m`를 출력하며 죽는다.

## 2. 도착 판정 1.0 m — 꼬리가 칸 밖에 남는다

링 경로에서 쓰던 `arrive_tol_m = 1.0`을 주차에도 그대로 썼다. 링에서는 1 m가 142 m 루프의
0.7%라 무의미하지만, 주차에서는 **차 길이의 22%** 다.

경로 끝 1.0 m 전에 멈추면 기준점이 2.64, 꼬리가 0.29 — 칸 입구(0.81)보다 **0.5 m 바깥**이다.
화면에서는 차가 구분선에 걸터앉은 것으로 보인다.

```python
park_arrive_tol_m = 0.15
```

같은 이유로 lookahead도 분리했다. 링은 최대 5.0 m를 쓰지만 진입 회전은 그보다 타이트하다.

```python
park_lookahead_m       = 1.6
park_final_lookahead_m = 0.8      # 남은 거리 < 4.0 m 일 때
```

## 3. 회전 반경 2.65 m — 차가 물리적으로 못 도는 값이었다

가장 비싼 버그다. 통로 x를 **−2.50으로 눈대중 고정**하고 반경을 거기서 파생시켰다:

```
r = (BAY_OPEN_X − AISLE_X) × 0.8 = (0.81 + 2.50) × 0.8 = 2.65 m
```

차량 한계는 `R_min = 2.86 / tan(0.6) = 4.18 m`다. **2.65는 그 63%다.**

커넥터에는 [19:27 문서](20260728_1927_ring-connector.md) §1.2에서 실현가능성 검사를 붙였는데
**베이 진입 회전에는 안 붙였다.** 같은 파일 안에서, 같은 종류의 회전인데, 한쪽만 검사했다.

증상은 제어 문제처럼 보였다: 차가 명령보다 덜 돌고, +y로 오버슛하고, 오른쪽 구분선에 붙는다.
사용자 표현이 정확했다 — *"차량입장에서 더 일찍 오른쪽으로 조향을 틀면 주차 공간 안에 들어올것같아"*.
곡률 클램프가 개입해 명령을 4.18 m로 자르고 있었으니, 경로는 2.65 m를 요구하고 차는 4.18 m를
그리고 있었다.

수정 — **통로 위치를 반경에서 역산한다.** 반대 방향이 애초에 틀렸다:

```python
TURN_RADIUS = MIN_TURN_RADIUS * RADIUS_MARGIN     # 4.18 × 1.25 = 5.23 m
AISLE_X     = BAY_OPEN_X - TURN_RADIUS            # 0.81 − 5.23 = −4.42 m
```

4분원은 x와 y로 각각 r만큼 변위를 만든다. 회전이 칸 입구에서 **끝나야** 하므로
`AISLE_X = BAY_OPEN_X − r`은 선택이 아니라 항등식이다.

### 3.1 대가: 통로가 IN 표시에서 1.66 m 멀어졌다

IN 표시는 x=−2.76에 있다. 통로가 −2.50일 때는 26 cm 차이라 사실상 표시 위였는데, 이제 **1.66 m**
떨어졌다.

의도한 게 아니라 기하가 밀어낸 결과다. IN 위에 통로를 두려면 반경 2.65 m가 강제되고, 그건
불가능한 경로다. **못 가는 경로보다 페인트를 1.66 m 비껴가는 편이 낫다**고 판단했다.
IN 표시는 진입 시 차량 오른쪽 1.66 m라 카메라 시야에는 그대로 남는다.

### 3.2 대가: 공유 통로가 5.60 m → 3.02 m로 줄었다

`turn_start_y = bay_y − r`이므로 r이 커지면 회전이 더 일찍 시작되고 직진 구간이 짧아진다.

서수 축이 공유 구간에 걸려 있으므로 이건 그냥 손실처럼 보이지만, **커넥터(13.32 m)가 앞에
붙으므로 실제 공유 접두는 16.12 m다.** 진입 전 링 주행이 있는 한 문제되지 않는다.

## 4. 호의 중심을 통로 위에 놓았다 (별개 버그)

3번을 고친 뒤에도 궤적에 꺾임이 남았다. 중심을 통로선 위에 두고 있었다:

```python
cx, cy = AISLE_X, turn_start_y          # 틀림
```

+y로 달리다 우회전하는 차의 순간 회전 중심은 **진행방향 오른쪽 r 지점**이다. 중심을 통로 위에
두면 호의 시작점이 직진이 끝난 곳에서 r만큼 떨어진 곳이 되어, 그 사이가 순간이동한다.

```python
cx, cy = AISLE_X + r, turn_start_y
P(t)   = (cx - r*cos t, cy + r*sin t)   # t: 0 → π/2
```

실측 결과: 수정 전 경로의 최소 반경은 설계값 5.23 m가 아니라 **2.64 m**로 측정됐다 —
꺾임 자체가 곡률로 잡힌 것이다. 수정 후 정확히 5.23 m.

**설계값을 믿지 말고 생성된 점열에서 다시 잴 것.** 이 버그는 그렇게만 잡힌다.

## 5. 실현가능성 여유를 두 개로 쪼갰다

하나의 마진(1.25)으로 "설계 목표"와 "거부 기준"을 겸하고 있었다. 그 결과 lane2 커넥터
(4.53 m = 한계의 1.08배)가 **주행 가능한데도 INFEASIBLE로 보고**됐다.

```python
RADIUS_MARGIN   = 1.25    # 자유롭게 설계하는 경로의 목표
DRIVABLE_MARGIN = 1.05    # 이 아래는 거부
```

- 베이 진입처럼 우리가 위치를 정할 수 있는 경로 → 1.25배(5.23 m)를 쓴다
- 커넥터처럼 양끝이 고정된 경로 → 1.05배(4.39 m)를 넘기면 통과, 클램프가 개입한다고 명시

lane2 커넥터는 이제 `DRIVABLE (clamp will engage)`로 보고된다. lane1은 2.96 m라 여전히 거부.

## 9. 교훈

**계측이 통과한다고 기하가 맞는 건 아니다.** `arrived`도 떴고 반사실 발산도 정상이었다.
아무도 "차체가 칸 안에 있는가"를 재고 있지 않았을 뿐이다. 지금은 생성기가
`clear_front_m` / `clear_rear_m` / `min_radius_m`를 출력한다.

**검사를 한 곳에 붙였으면 같은 종류의 다른 곳에도 붙일 것.** 커넥터에는 실현가능성 검사가
있었고 베이 진입에는 없었다. 같은 파일, 같은 종류의 회전이었다.

**파생 방향을 확인할 것.** 통로 위치를 정하고 반경을 파생시키면 불가능한 값이 조용히 나온다.
반경은 차량이 정하는 상수이므로 통로가 그것을 따라야 한다.
