## 1. 리샘플러가 10 ms 때문에 11개 중 10개를 버렸다

```
accepted : 1 / 11
rejected : 10x  "grid point 0 outside the pose stream"
```

실측:

```
frames   316.141 .. 367.423
cli      316.151 .. 367.494      ← 첫 프레임보다 10 ms 늦게 시작
```

격자 원점 `t0`를 **프레임 스트림에만** 묶어두고 있었다. 이미지 콜백과 pose 스레드는 독립적으로
시작하므로 첫 프레임이 첫 pose보다 몇 ms 앞서는 것은 일상적이다. 10 ms는 주행거리 0.7 cm다.
데이터에는 아무 문제가 없다.

수정 — 원점은 **모든 스트림이 값을 가지는 시점 이후**여야 한다:

```python
floor_t = poses[0]["t"]
if control:  floor_t = max(floor_t, control[0]["t"])   # ZOH는 첫 명령 이전에 잡을 값이 없다
if settled_t is not None:  floor_t = max(floor_t, settled_t)
t0 = 첫 프레임 중 t >= floor_t
```

결과: **11/11 통과**, nearest-error 중앙값 8.0 ms (게이트 17 ms), 격자점 5756개.

### 1.1 드라이버가 `settled`를 보내지 않고 있었다

리샘플러는 `settled` 이벤트를 격자 원점으로 쓰는데(`resample_episodes.py:218`) 수집 드라이버가
그걸 발행하지 않았다. 그래서 리셋 직후 **차가 정지해 있는 구간이 데이터에 들어갔다** — 기록은
이미 시작됐고 명령은 아직 안 나간 창이다. 학습에 들어가면 "명령을 받은 직후에는 가만히 있어라"가 된다.

명령 발행 시점에 표시하도록 추가했다.

## 2. `measure_cmi.py` — 무엇을 재는가

다른 지표들은 전부 **궤적 전체**를 비교한다. 이건 정책이 실제로 맞닥뜨리는 질문을 묻는다.

> 여기 서서, 이걸 보고 있을 때, 문장이 다음 행동에 대해 얼마나 알려주는가?

조건을 거는 것이 핵심이다. 조건 없는 `I(action ; instruction)`은 부풀리기 쉽고 의미가 없다 —
bay1과 bay4 에피소드는 끝나는 곳이 다르니 행동도 다르고 따라서 상호정보가 크지만,
**관측만 보는 정책도 똑같이 잘한다.** 관측으로 조건을 걸면 그 부분이 정확히 제거되고,
남는 것은 문장이 설명하고 시야가 설명하지 못하는 부분이다.

관측 버킷은 GT pose를 양자화해 쓴다(1 m, 15°). 이미지 특징보다 **더 강한** 조건이다 —
정적 월드에서 pose는 렌더링된 화면을 정확히 결정하므로 한 버킷 안의 표본은 구성상 동일한
이미지를 갖는다. 이미지 특징으로 묶으면 "비슷해 보이는" 화면들이 섞이면서 위치 정보가
잔차로 새어든다.

## 3. 지표 설계 오류 2건

### 3.1 Miller-Madow 부호를 반대로 넣었다

보정을 적용했더니 값이 **커졌다**(0.553 → 0.693). 보정은 추정치를 줄여야 한다.

Miller-Madow는 각 엔트로피에 `(support−1)/(2n ln2)`를 **더한다**. 결합 support가 셋 중 가장 크고
음부호로 들어가므로 순 보정항은 음수다 — plug-in MI가 위로 편향된다는 사실 자체가 이 보정을
쓰는 이유다. `h - corr`로 썼는데 `corr`이 음수라 부풀렸다.

### 3.2 행동 알파벳이 커서 추정이 편향에 잠겼다

초기 결과:

```
I(a;instr|obs)      0.553 b
shuffled control    0.520 b     ← 연관을 완전히 파괴한 대조군이 거의 같다
```

셔플 대조군은 **버킷 안에서 instruction 라벨만 뒤섞은 것**이다. 주변분포는 그대로고 연관만
사라진다. 거기서 나오는 값은 전부 편향이다. 실제값과 대조군이 1.3배 차이라는 것은
**측정값의 대부분이 편향**이라는 뜻이다.

행동을 `(dyaw, forward_step)` 2채널로 잡아 결합 알파벳이 컸다. 서수 축의 주장은 **어디서 도는가**,
즉 dyaw다. 1채널로 줄이니 대조군이 0.059로 떨어졌다.

지금은 **디바이어스 값**(plug-in − 셔플 평균, 순열 20회)을 주 지표로 보고한다.

### 3.3 그리고 진짜 문제 — 단일 스텝으로 재고 있었다

1채널로 고친 뒤 디바이어스 중앙값이 **0.002 bit**로 나왔다. 구 스택과 같은 수치다.

하지만 이건 데이터가 아니라 자의 문제다. **정책이 내는 것은 액션 청크다.** SmolVLA는 수십 스텝을
한 번에 출력하므로 시점 t의 예측 대상은 100 ms가 아니라 수 초다.

`horizon=1`은 "문장이 다음 0.1초를 바꾸는가"를 묻는다. 공유 통로를 직진하는 동안 정답은
**어느 칸이든 아니오**다 — 명령이 아직 관련되지 않았을 뿐이다. 그렇게 재면 코퍼스가 0 bit를
받고 구 스택처럼 보이는데, 이유가 완전히 다르다.

지평선을 늘려 다시 재니 구조가 드러난다 (11 에피소드 스모크, ordinal 축 4개):

| 지평선 | 디바이어스 중앙값 | 셔플 바닥 |
|---|---|---|
| 0.1 s | 0.000 b | 0.059 |
| 1.0 s | 0.251 b | 0.181 |
| **2.5 s** | **0.377 b** | 0.248 |
| 5.0 s | 0.334 b | 0.401 ← 바닥에 잠김 |

기본값을 **2.1초**(계획서 §5.6이 명시한 평가 시점)로 뒀다.

5초에서 다시 내려가는 것은 신호가 줄어서가 아니라 에피소드가 4개뿐이라 긴 지평선에서
독립 표본이 부족해서다. **본 코퍼스(ordinal 180 에피소드)에서 다시 재야 한다.**

## 6. 교훈

**대조군 없는 정보량 추정치는 읽지 말 것.** 첫 측정의 0.553 bit는 그럴듯해 보였고 실제로는
0.520이 편향이었다. 버킷 안에서 라벨만 섞는 순열 검정이 20줄이고, 그게 없으면 숫자가 무슨
뜻인지 알 수 없다.

**지표는 예측 대상과 같은 것을 재야 한다.** 정책이 청크를 내는데 단일 스텝으로 재면 0이 나온다.
데이터가 아니라 자가 틀린 경우가 오늘만 세 번째다 — 공유 접두(인덱스 vs 호길이),
속도 스케줄(호길이 vs 시간), 그리고 이번(스텝 vs 청크).
