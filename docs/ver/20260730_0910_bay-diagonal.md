밤사이 v2b(주차+패딩)가 완주했고, 아침 디버깅으로 **"말한 칸에 정확히 들어가는"** 상태에

## 1. v2b 첫 시험 — 패딩으로도 0/8, 그러나 원인이 달랐다

4칸 × 2회 혼동행렬: 전부 정지 실패, 끝점이 명령과 무관하게 통로 끝쪽으로 몰림.
패딩 실패로 보였지만 **분리 시험을 먼저** 했다.

## 2. 분리 시험 — 오라클 액션 재생이 4 m 빗나갔다

스텁 서버의 replay 모드로 **기록된 오라클 액션을 그대로** 브릿지에 통과시켰다.
정책 없이도 bay2를 4 m 지나침 → **서빙 경로 유죄.**

### 2.1 범인: 횡슬립을 속도에 합산

```python
v = math.hypot(dx, dy) / dt      # 틀림
v = dx / dt                      # 수정
```

액션의 dy는 차량 기준점(뒤차축 1.554 m 앞)의 **횡슬립**이다 — 회전 중 |dy|/dx ≤ 0.41
(레코더 디버깅 때 실측). hypot으로 합치면 회전 중 v가 ~8% 부풀고 곡률 k=w/v가 같은 비율로
줄어 **체계적 언더스티어**가 된다. 슬립은 차량 기하가 스스로 재현하므로 전진 성분만 명령해야
한다.

수정 후 재생: **4/4가 bay2 사각형 안, 전원 정지** (중심 오차 0.58~1.24 m).
서빙 경로 무죄 판정. **어젯밤 RR 0.35도 이 버그가 깎아 먹은 수치였다.**

### 2.2 replay 모드 자체의 버그

재생이 에피소드 끝에서 처음으로 wrap해 주차 후 차가 다시 출발했다. 끝에서 zero-action
클램프로 수정. 하마터면 "주차 후 재출발"을 서빙 경로 결함으로 오진할 뻔했다.

## 3. 정지는 배웠는데 폐루프에서 왜 안 멈추나 — 2분 진단

체크포인트를 직접 심문:

```
정지 화면 + 속도 0    → 0.003 m/s   (멈춘 채 유지 ✓)
정지 화면 + 속도 1.2  → 0.171 m/s   (급감속 ✓)
중간 화면 + 속도 1.2  → 0.750 m/s   (주행 유지 ✓)
```

**패딩은 효과가 있었다.** 폐루프 실패는 추종이 어긋나 차가 학습된 "정지 화면"에 도달하지
못했기 때문 — 정지 스킬이 아니라 추종 정밀도의 문제였다.

## 4. 커밋 길이 스윕 — 서빙의 결정적 파라미터

행동 신선도를 높이려 리필을 앞당겼더니 **정반대**가 나왔다:

| refill_at | 청크당 실행 | 결과 |
|---|---|---|
| 0.93 | ~6개 (0.6 s) | **전원 한 점으로 붕괴.** 언어 분화 소멸 |
| 0.7 | ~12개 (1.2 s) | bay2·bay3만 정답, 극단 실패 |
| **0.3** | **~21개 (2.1 s)** | **8/8 정답 칸** |

이유: 청크의 **앞부분은 공유 통로 접두라 어느 칸이든 같고, 회전 결심은 뒷부분**에 있다.
자주 재계획하면 앞부분만 실행하고 결심을 계속 버린다 — 다중 모드 궤적에서 receding-horizon이
평균(직진)으로 퇴화하는 병리. 오라클 재생이 완전 open-loop으로도 정확했으므로 개별 계획은
중간 수정 없이 충분히 정확하고, **길게 커밋하는 쪽이 옳다.**

`refill_at` 기본값을 0.3으로 바꾸고 스윕 표를 코드 주석에 박았다.

## 5. 도달한 상태 (v2b + 수정된 브릿지)

```
confusion (commanded → reached):
  bay1: [bay1, bay1]     bay2: [bay2, bay2]
  bay3: [bay3, bay3]     bay4: [bay4, bay4]      ← 8/8
끝점 y: -7.9 / -5.2 / -1.9 / +1.0  (칸 중심 -9.4 / -5.7 / -2.1 / +1.5)
칸 사각형 안: 6/8
```

**잔여 결함 — 미세 크리프**: 올바른 칸 진입 후 0.05~0.08 m/s로 계속 기어감 (75초에
x가 1~2 m 깊어짐). flow matching 회귀가 정확히 0을 못 내는 잔차다. 제어 경로 데드밴드는
기준 (d) 위반이라 쓰지 않는다. 후보: hold 프레임 증량(45), 말단 구간 oversample — v21b
결과를 보고 결정.

## 6. 운영 사고 1건 (기록)

v21b 파이프라인이 01:58에 조용히 실패해 **GPU 0이 6시간 놀았다.** SSH heredoc 명령이
exit 143으로 죽으며 스크립트 생성부터 실패했는데, 감시 모니터가 **중단된 구 run의 로그
잔재에 반응해** 진행 중으로 오판했다. 재발 방지: (1) 원격 실행은 로컬 작성 + scp,
(2) 런처 exit code가 아니라 **원격 상태(새 로그 파일 존재·프로세스)를 직접 검증**,
(3) 감시는 새 run 전용 로그 파일만 본다.

이후 혼선 1건 더: 재시작 pkill이 래퍼만 죽여 hold-15 학습이 살아남았다. 데이터 손상은
없음을 확인했고, hold-15도 정지를 가르친다는 것이 검증돼 있어 **그대로 완주시키기로 결정**
(hold-30의 한계 이득 < 재학습 4.5시간).
