# 2026-08-24 11:06 — v8g 축 프로브: 목표 채널은 "들리지만" 도달은 실패

v8g(목표 조건화: state 5D = [v, ω, δ, goal_bearing, goal_dist]) 60K 체크포인트의
4종 축 프로브 결과. 실행: `tools/eval/bringup_bare_sim.sh` + `tools/eval/v8g_axis_probe.sh`
(bare-sim, max_speed 3.2, slew 0.08, model_name:=ego_vehicle).

|---|---|---|---|

- **v8 대비 전진**: v8은 직행 문장에 목표별 반응 자체가 없었다(20260822_1010).
  v8g는 근거리에서 목표 정체성에 따라 궤적이 54× 갈라진다 — goal_bearing/dist
  상태 채널이 정책에 입력되고 있다는 증거.
- **여전히 실패**: 갈라지되 목표로 조향하지 않는다. 종점은 v8 실패와 같은
  북서 이탈 지대((−9,45), (−43..−56, 36..53)). 존 정체성→조향 그라운딩이
  아니라 "직행 문장 = 링 이탈" 수준의 모방에 머묾.
- 원거리(49m, 학습분포 8–30m 밖)는 같은 문장 반복조차 14m 갈라짐 —
  분포 밖에서 정책이 사실상 무작위 배회.

## 서빙 인프라 버그 3건 수정 (이번 프로브를 이틀 막은 것들)

1. **서버 워밍업 상태 차원 하드코딩** — [vla_policy_server.py](../../src/nav_vla_pkg/scripts/vla_policy_server.py)
   워밍업이 3D 고정 → 5D 정규화기와 충돌로 기동 크래시. config.input_features는
   smolvla_base의 가짜 메타데이터(state=[6], 유령 카메라 5개)라 못 믿는다 —
   **정규화 통계 safetensors에서 차원을 읽도록** 수정.
2. **프로브 무한 대기** — v8g_axis_probe.sh의 `until grep 'serving on'`이
   서버 사망 시 영원히 대기(실제 2일 행). 3분 타임아웃 + 서버 생존 감시로 교체.
3. **bare-sim 모델명 불일치** — 브리지 기본 `prius_hybrid` vs bare-sim 차량
   `ego_vehicle` → 목표 포즈를 못 찾아 추론 요청이 안 나감(차 정지).
   프로브에 `-p model_name:=ego_vehicle` 추가.

## 직행 저속 문제 (별건, 데이터 이슈)

직행 주행 속도 0.65~0.8 m/s로 기어감. 원본 v8 직행 데모는 정렬 후 p90
3.0~3.8 m/s로 빠름 — 데이터 잘못이 아니라 **정책이 자기 속도 상태 피드백의
저속 평형점에 갇힘**(2026-08-05 speed_scale 무용 기록과 동일 기전). 직행
문장에는 속도 절이 없어(템플릿에 슬롯 없음) 문장 앵커도 없다. 후보 수정:
직행 템플릿에 속도 절 추가 + `direct_turn_speed` 티어 승격 후 직행 그룹 재수집.

## 다음 이터레이션 재료 (20260822_1010의 후보 + 이번 증거)

- 목표 채널이 들리는 건 확인됐으니, 실패는 **시각-존 그라운딩/정책 용량** 쪽.
  (a) 직행 비중 확대 + 존 시각 앵커 구도, (b) 거리 커리큘럼(근거리부터),
  (c) goal_bearing 부호/좌표계 검증(브리지 계산 vs 학습 라벨 일치 확인)이 우선순위.
- 직행 문장은 여전히 정책을 트랙 밖으로 유도 — **데모에서 직행 문장 금지 유지**.
